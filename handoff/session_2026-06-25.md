## Decisions Made

- **Notification consent model**: transactional notifications (booking confirmation, cancellation, contact form) always send under GDPR Art. 6(1)(b); reminders also treated as transactional per user decision
- **Telegram for notifications**: admin/master only for now; client Telegram is a future feature tied to "register via Telegram" flow
- **SMS**: deferred — left a thin abstraction; n8n can be wired externally if needed
- **Telegram bot token**: stored in `TenantConfig.telegramBotToken`, configurable directly from Notifications settings page (same field as Social Auth)
- **Dedup granularity**: per `(appointmentId, type, channel)` — disabled channels count as "done" to avoid wasted DB queries on each cron tick
- **Switch component**: uses Base UI (not shadcn Radix) — `data-checked` on Root, not Thumb; `group-data-[checked]/switch:` is the correct selector pattern
