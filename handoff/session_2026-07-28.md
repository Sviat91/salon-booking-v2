## Decisions Made

- **Discount "Active from/until" gates the appointment's date, not the booking date.** Reverses the original discounts-feature plan's AD-5. Reasoning: matches the user's actual mental model, confirmed via live testing (a period set to bracket a future appointment should apply to that appointment even if booked earlier).
- **"Today's promotions" card only shows discounts that don't require a promo code** (codes must stay secret) **and reacts to the selected service** rather than being static — decided through back-and-forth after the user's first, vaguer request for "some small text."
- **Docker for the app, Nginx+Certbot on the host (not containerized)** for deployment — chosen specifically because `certbot --nginx` needs to edit a real host Nginx config to work exactly as the user described, while Docker still solves the actual reliability risk (Node/native-module version drift across different clients' VPSes).
- **Multiple client instances per VPS, not one-VPS-per-client** — user's explicit choice; drove the port-registry/naming-isolation design in `deploy/install.sh`.
- **Update/upgrade tooling for already-deployed client instances is explicitly out of scope** — user's explicit choice, first-install only for now.
- **Cloudflare Turnstile keys are prompted for interactively** by the install script — can't be generated, they're domain-bound and require a manual Cloudflare registration step per client.
