## Decisions Made

- **adminPermissions stored as JSON string on User** — consistent with existing pattern (`intervals`, `logoPages`), avoids extra join table for a simple 6-boolean payload
- **adminPermissions NOT in JWT** — prevents stale cache; API routes and server components read from DB at request time for ADMIN users; SUPERADMIN always gets ALL_PERMISSIONS by role check alone
- **DB Browser is SUPERADMIN-only read+delete** — full CRUD skipped for now; delete covers the main operational need (removing bad/test data); schema editing is out of scope
- **Footer hidden via CSS `:has(.admin-layout)`** — zero JS, no layout restructuring; works because `.admin-layout` class is already on the admin wrapper div
- **GDPR erase uses direct record ID** — unlike the public GDPR endpoint (phone+name lookup), admin panel erases by ID which is appropriate given the admin is authenticated and has explicit `gdpr.erase` permission
- **SuperAdmin credentials in Settings page** — avoids a new route; naturally grouped with other account-level config; gated by role check server-side
