- **Fixed "Also apply to dark theme" background checkbox no-op bug** (LIGHT mode: orchestrator-authored plan → coder → reviewer, approved). User reported checking the box and uploading a light-theme background image had zero effect on the dark theme. Root cause: `src/app/layout.tsx`'s dark-theme background CSS block never read `config.bgApplyToDark` at all — it always rendered the independent `darkBg*` fields. Fixed by sourcing the dark block from the light theme's own `bgType`/`bgImageUrl`/`bgGradient*` values when the flag is true and light `bgType !== 'solid'`, falling back to the original independent behavior otherwise. Change confined to `src/app/layout.tsx`.

## Decisions Made

- SMS provider: build both Twilio and SMSAPI.pl behind one shared interface (not locked to one vendor), BYO API keys per salon rather than centrally billed.
- Editable-template scope stayed narrow (24h/2h reminders only, not confirmation/cancellation) even after widening from SMS-only to all three channels — user's explicit, repeated choice.
- Email template editing: admin controls only the message text; the HTML wrapper/branding/subject line stay fixed and out of admin control, to prevent an admin from accidentally breaking the email's layout.

- Fake placeholder data style: used deliberately generic, recognizable placeholder values ("Kwiatowa" street — the Polish equivalent of "Main Street" — and a sequential fake phone number) rather than another realistic-looking fabricated address, to make it obvious at a glance that it's an example.
- Every fix this session was scoped as SINGLE/LIGHT (orchestrator investigates and writes the plan directly) rather than FULL/planner, once the root cause was fully understood — reserving planner for the two genuinely architectural pieces (SMS channel, multi-channel templates).
