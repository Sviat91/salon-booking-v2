## Decisions Made

- Mobile calendar: everything gated by `isMobile`/`lg:` so desktop stays byte-for-byte unchanged; header date (not the grid) navigates to Day to avoid accidental taps; Agenda is mobile-only with a Week fallback on desktop.
- Google auth = one service account per salon (not OAuth: no Google app verification, no refresh-token expiry, less friction); key uploaded as a file and encrypted, never displayed again; explicit enqueue calls (not a Prisma `$extends`) so pull can never trigger a push; outbox table for retries; no new dependency.
- Foreign Google events are a separate read-only table (an `Appointment` requires a client + service); title→line 1, first description line→line 2, fallbacks localized at display time; conflicts only notify; never auto-delete.
- Google-side time change/deletion of a site-made event is applied to the site with a salon-Telegram-only notice (client not notified, deliberately); Google text edits of site-made events are not applied back; site wins while a push is pending.
- External-block overlap checks run just before booking transactions, not inside them (avoids stalling interactive libSQL transactions; the appointment-vs-appointment guard inside the transaction is untouched).
- Orchestration this session: LIGHT for UI work, FULL (planner→coder→reviewer) for the sync; reviewer findings with a fully understood fix were resolved by the orchestrator/coder directly without re-invoking the planner; the reviewer agent has no Write tool, so the orchestrator saved its feedback files.
