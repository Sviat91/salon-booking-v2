- **Root cause found (important, systemic)**: this project's Tailwind config (`tailwind.config.ts`, v3.4.17) does not register a `theme.data` map, so **bare `data-foo:` variants (no brackets) compile to nothing** — Tailwind's `matchVariant('data', ...)` only works via `theme('data')` lookup or bracket syntax `data-[foo]:`. Confirmed by grepping the actual compiled `.next/static/css/*.css` output: `data-highlighted:`, `data-open:`, `data-closed:`, `data-disabled:` in `select.tsx` produced **zero CSS rules**, silently. This was not caught earlier because both the reviewer subagent and my own "verification" only checked source code / grepped for token names, never the actual generated selector rules.
- Fixed `src/components/ui/select.tsx` to use bracket syntax (`data-[highlighted]:`, `data-[open]:`, `data-[closed]:`, `data-[disabled]:`), matching the pattern already proven to work elsewhere in the codebase (`switch.tsx`'s `group-data-[checked]/switch:`). Verified this time by grepping the compiled CSS and finding real rules: `[data-highlighted]{background-color:var(--md-primary-container)}`, `[data-open]{--tw-enter-opacity:0}`, `[data-disabled]{opacity:.5}`.
- Every round independently re-verified with `rm -rf .next && npm run build` (73 pages, clean) and `npm run lint` (61 problems, matches pre-existing baseline, 0 new) — never trusted a warm-cache build or subagent self-report alone.
