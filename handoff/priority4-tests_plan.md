## Architecture Decisions

### The one high-leverage infra fix — next-auth's `next/server` resolution (unblocks 5 files)
- **Symptom:** `Cannot find module '.../node_modules/next/server' imported from next-auth/lib/env.js`. It fires whenever a test imports a **route handler that imports `@/auth`**, because `@/auth` → `next-auth` (beta) → `next-auth/lib/env.js` → `import 'next/server'`, and Vitest's `node` environment doesn't resolve next-auth's conditional `next/server` export. `next/server` DOES resolve when a route imports it directly (that's why non-auth route tests import fine) — the failure is specific to next-auth's internal import.
- **Affected files (each imports a route that imports `@/auth`):** `book/route.ts` → `consent-gate.test.ts` (0 tests collected — file fails to load) and the two `POST /api/book` tests in `routes.test.ts`; `consents/erase/route.ts`, `consents/export/route.ts`, `consents/withdraw/route.ts` → the three consent tests.
- **Decision: mock `@/auth` in each affected test file** with `vi.mock('@/auth', () => ({ auth: vi.fn().mockResolvedValue(null) }))` (place BEFORE the route import; for `beforeAll`-dynamic-import files, at module top). This is deterministic, avoids transforming next-auth at all, and is **semantically correct** — every one of these tests exercises the unauthenticated/guest path (guest booking, guest GDPR erase/export/withdraw), which is exactly `auth() → null`. `vi.mock('@/auth', …)` resolves via the `@` alias already configured in `vitest.config.ts`.
- **Rejected alternative:** a global `test.server.deps.inline: [/next-auth/, /@auth\/core/]` (or `deps.optimizer.ssr`) in `vitest.config.ts` — it's the "one-line config fix" the brief hinted at, but it forces Vitest to transform the whole next-auth beta chain (which pulls in React/edge shims) and is riskier and less predictable than mocking the single `@/auth` boundary. Keep it in the back pocket only if a route turns out to import auth transitively in a way `vi.mock('@/auth')` can't intercept.

### Two justified deletions — tests for permanently-removed functionality (call out explicitly)
- **`tests/lib/availability.categories.test.ts` → DELETE.** It `vi.mock`s `../../src/lib/google/sheets` and `../../src/lib/google/calendar` (both **deleted** in Priority-2, session 2026-07-13 — `src/lib/google/**` no longer exists) and calls `getAvailableDays(from,until,dur,{ procedureCategory })` / `getDaySlots(date,dur,step,undefined,category)`. The current `availability.ts` is DB-driven (via `schedule-utils`), takes `masterId` not `procedureCategory`, and has **no per-day category-exception rules** — that feature was part of the removed Google-Sheets availability model. This test covers functionality that is permanently gone; there is nothing current to re-point it at. **Delete it.**
- **The two `POST /api/book` tests inside `tests/api/routes.test.ts` → REMOVE (from that file).** They mock the removed `google/calendar` (`createEvent → { id: 'evt-123' }`) / `google/sheets` (`readProcedures`) and assert `{ ok: true, eventId: 'evt-123' }` — the old Google-Calendar-backed book flow. The current `book/route.ts` is DB-based, returns `{ eventId }`, and is already covered end-to-end (consent gate, guest creation, `$transaction` conflict re-check, appointment create) by `tests/app/api/book/consent-gate.test.ts` — which this plan repairs. Removing the two obsolete Google smoke tests loses no real coverage. **Called out as a removal of removed-architecture tests, not silent.**

### Current-behavior anchors the rewrites must target (verified against source)
- **`canModifyBooking(startTime: Date)`** → `{ canModify: boolean, reason?, hoursRemaining? }`; `canModify` is `false` when `< 24h` before `startTime`, else `true`.
- **`normalizePhoneToE164(input)`** (Poland-default, throws `Error('INVALID_PHONE')` on invalid): `'123 456 789' → '+48123456789'`; `'123-456-789' → '+48123456789'`; `'+48123456789' → '+48123456789'`; `'48123456789' → '+48123456789'`; `'0123456789' → '+48123456789'`; bare/trunk-0 Ukrainian mobiles now normalize to **`+48…` (no UA heuristic)** — e.g. `'0501234567' → '+48501234567'`, `'50 123 45 67' → '+48501234567'`; international WITH `+` is preserved (`'+380501234567'`, `'+491234567890'`, `'+447911123456'`, `'+33123456789'`); `'380501234567' → '+380501234567'` (12 digits, no `+`, treated as full international); `'' → ''` and `'   ' → ''`; **too-short like `'12'` → throws `INVALID_PHONE`** (fails the `+[1-9]\d{6,14}` check). `normalizePhoneDigitsOnly('+48 123-456-789') → '48123456789'`.
- **`string-normalization` exports:** `normalizeNameForMatching(s)` = `s.trim().toLowerCase().replace(/\s+/g,' ')`; `normalizeEmailForMatching(s)` = `s.trim().toLowerCase()`; `normalizeSearchQuery(s)` = same as name; `normalizeTextWithCyrillicConversion(s)` = lowercase+trim + a **partial** cyrillic→latin map (only а е о р с у х к м н в т) — e.g. it does NOT fold Polish diacritics and does NOT fully transliterate; write assertions to its real output, not to an idealized transliterator.
- **`getDaySlots(dateISO, minDuration, stepMin=15, masterId?)`** → `{ slots: {startISO,endISO}[] }`; empty when no `masterId`, day-off, or no open window; slots are step-aligned within (open windows − busy), and past slots are trimmed when `dateISO` is "today" in `Europe/Warsaw`. **`getAvailableDays(fromISO, untilISO, minDuration, { masterId })`** → `{ days: {date,hasWindow}[] }`. Both read `readWeeklyFromDb` / `readOverridesFromDb` / `fetchBusyRanges` from `@/lib/schedule-utils`.
- **`schedule-utils` mock shapes (for Step F):** `readWeeklyFromDb(masterId) → Map<number/*0-6 dow*/, { isDayOff: boolean, intervals: {start:string,end:string}[] }>`; `readOverridesFromDb(masterId, from, until) → Map<string/*YYYY-MM-DD*/, {isDayOff, intervals}>`; `fetchBusyRanges(masterId, dateISO) → { start:number, end:number }[]` (minutes since midnight). Keep the pure helpers (`intervalsToRanges`, `minusBusy`, `t2m`, `isoDate`, `jsDayOfWeek`, `SCHEDULE_TZ`) REAL via `vi.importActual` and mock only the three DB readers.
- **`support/contact/route.ts` current contract:** Zod-validate (400 `VALIDATION_ERROR` with `field`) → `rateLimit(\`rate:support-contact:${ip}\`, 3, 900)` (429 `RATE_LIMITED`) → `log.info({ …, email: maskEmailForLog(email) }, 'Contact form received')` (`'user@example.com' → 'u***r@example.com'`) → `notifyContactForm({ senderName, senderEmail, subject, message }).catch(...)` (fire-and-forget) → 200 `{ status:'success', message:'Wiadomość została wysłana pomyślnie…', requestId }`. It does NOT read `@/lib/env`, does NOT fetch N8N directly, has NO retry/503/502 logic (that moved into `@/lib/notifications`). Fields are Zod-`.trim()`'d but email is NOT lowercased.
- **`consent-gate.test.ts` current book route:** wraps the conflict re-check + `appointment.create` in `prisma.$transaction(async (tx) => …)` and returns `{ eventId: created.id }`; uses `@/lib/consent-service` (real, over the mocked prisma) for the consent gate; `notifyBookingConfirmation(id).catch(...)` is fire-and-forget.
