## Decisions Made

- **Long polling, not webhook** (confirmed working end-to-end this session) — no public URL/tunnel needed, works identically on localhost and the VPS. This was the single biggest architecture decision of the whole bot project and it held up through the entire build without needing reconsideration.
- **`instrumentation.ts` must live at `src/instrumentation.ts`, not repo root**, for any project using a `src/` directory — a genuine Next.js framework gotcha, not obvious from reading the file's own contents, only surfaced via live testing (the file compiled fine, `tsc`/`build` never caught it).
- **Client-side caching needs explicit opt-out at TWO separate layers** (React Query's own `staleTime` AND Next.js's independent Client-side Router Cache) — fixing one alone looked like it worked but didn't fully resolve stale-calendar complaints; both had to be disabled for the "always fresh, DB is local, no request-volume concern" principle the user established early in the session to actually hold everywhere.
- **Website URL for the bot lives in the DB (`TenantConfig.clientBotSiteUrl`), not only `.env`** — the user (non-technical, admin-UI-only persona) explicitly doesn't want to touch server environment variables; falls back to `NEXT_PUBLIC_SITE_URL` if the DB field is empty, preserving compatibility for anyone who already set the env var.
- **`localhost` URLs are a known, accepted limitation for Telegram URL buttons specifically** (not for the rest of the app) — documented in the Settings UI copy rather than worked around, since it's fundamentally about reachability from an arbitrary external device (a phone), not something the app can fix.
- **Reminder delivery via the client bot is explicitly out of scope for this session** — `User.telegramChatId` persistence was built (foundation only) but actually sending reminder messages through the bot was deliberately deferred at the user's own direction, to be picked up as a separate future round.
- **Booking management (cancel/reschedule) via the bot remains out of v1 scope**, per the plan's original Architecture Decision #9 — confirmed still standing when the user asked about it mid-session; not reconsidered or built.
- **Never log raw grammy error/context objects** — established as a hard rule this session after the live token-leak find; the `describeError()` pattern (extract `.name`/`.message` only, never pass the object itself to `console.*`) should be the template for any future logging added to the bot module.
- **Any Telegram message with a `url`-type inline button must have a try/catch + no-URL-button retry** — established as a resilience pattern after the wizard-hang find, applied at both current call sites (consent prompt, booking-success message); worth applying to any future URL-button usage in the bot.
