- Added `sharp` to `package.json` `dependencies` — required by Next.js standalone mode for `next/image` optimization; was never installed, silently broke every optimized image in production (`'sharp' is required...` in server logs).
- `next.config.mjs`: `images.unoptimized: true` — the real, permanent fix. Next's `/_next/image` optimizer (and its own static file serving) only recognizes files present in `public/` at **process boot**; anything uploaded while the container is already running 404s/400s until next restart. Disabling optimization makes every `<Image>` render a plain `<img src>`, sidestepping this for all 15+ consumers at once instead of fixing them one by one.
- `src/app/api/masters/route.ts`, `src/app/api/tenant-config/route.ts`: added `export const dynamic = 'force-dynamic'`. Both are zero-argument `GET` handlers with no auth/cookies/searchParams usage, so Next.js was statically caching the very first response **forever** in production (`next start`) — newly added masters, and any branding/theme change read via these endpoints, would never appear without a rebuild. Invisible in `next dev`, which is why "works locally, broken on prod" kept recurring.
- `MasterSelector.tsx`: the hover-only "book visit" row under a master's name was `opacity-0` (still occupying layout height), pushing the name higher than the card's bottom edge and covering part of the photo. Changed to `hidden`/`group-hover:flex` so it takes zero space until hovered.

## Decisions Made

- **`images.unoptimized: true` over fixing 15 individual `<Image>` call sites**: given the actual root cause (Next standalone's boot-time file snapshot) affects every current *and future* consumer of `/uploads/*` content identically, a global one-line config change was judged more correct and maintainable than chasing each component — see `deploy/AGENTS.md` AD-14 for the reasoning trail (including the earlier piecemeal fixes to favicon/logo/master-form previews that turned out to be treating one symptom of this same disease).
- **Nginx config is a host file, not part of the repo's deploy automation** — `install.sh` only renders it once at first install; `git pull` + rebuild never touches it. This was the direct cause of the live server's nginx config being stale relative to the repo template mid-session, and is now called out explicitly in AD-14 as a standing gotcha for anyone debugging "works after fresh install, breaks after redeploy"-shaped issues.
- **`bio_pl`/`bio_en`/`bio_uk` DB columns kept as-is** for the Title-field rename — repurposing an existing nullable string column (new label/widget/validation only) stayed LIGHT mode; renaming the columns themselves would have required a migration for zero functional gain, so was explicitly rejected.
- **Master avatar upload reuses `resizeImageIfNeeded`/`<img>` pattern directly** rather than going through another full plan→coder→reviewer cycle — classified as `Mode: SINGLE` since it was a byte-for-byte repeat of a pattern already reviewed twice earlier the same day, and production was actively blocked.
