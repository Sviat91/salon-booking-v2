## Decisions Made

- **E.164 phone comparison** (not last-9-digits, not digits-only full match) — closes the cross-country suffix vulnerability while not regressing pre-existing un-migrated phone rows.
- **`$transaction` over a DB unique constraint** for the double-booking race — the conflict check is an overlapping-range query, not an exact-slot match, so a unique index wouldn't close the gap.
- **CSP with `unsafe-inline`, not nonce-based** — `layout.tsx` renders several inline scripts with per-request dynamic content; nonce hardening deferred as a known, explicitly-flagged trade-off. Made dev-mode-aware (adds `unsafe-eval`/`ws:` only in development) after it broke local dev hydration.
- **`git rm --cached` only, no history rewrite** for the leaked `app.db`/`uploads` — full history scrub is a separate, explicitly-requested task.
- **`canModifyBooking()` consolidation over deletion** — the function was dead code (orphaned when its old caller file was deleted in a June 2026 refactor), but rather than deleting it or leaving it unused, the triplicated inline logic in 3 live routes was replaced with calls to it, making it live code and eliminating real duplication.
- **i18n API error architecture: client-side `code → i18n` mapping**, not server-side per-request translation — the server/API layer has no access to the user's selected language (stored only in `localStorage`), so it must not bake translated prose; the existing `code` field already exists for exactly this purpose.
- **i18n plan split into 3 files** (Foundation/Client/Admin), mirroring the successful Priority-4 cleanup+tests split pattern — keeps each part independently reviewable and lets execution stop at checkpoints rather than one unwieldy plan.
