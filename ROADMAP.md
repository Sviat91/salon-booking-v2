## 🔴 Приоритет 1 — Критичные дыры в безопасности (сделать в первую очередь)

Источник: `app_review.md` (аудит от 2026-07-02, проверено сегодня — актуально).

1. **`/api/debug-db` — публичный эндпоинт без пароля.**
   Отдаёт реальный ID мастера + все графики/выходные. Просто удалить файл `src/app/api/debug-db/route.ts`. 5 минут работы.

2. **Можно менять чужую запись, зная её ID.**
   `PATCH /api/bookings/[id]` — нет проверки, что запрос от владельца записи. Любой, кто узнает ID, может поменять время/услугу.
   Файл: `src/app/api/bookings/[id]/route.ts`. Нужно добавить такую же проверку по телефону, какая уже есть в соседних роутах (`cancel`, `update-time`, `update-procedure`).

3. **Слив истории записей клиента по телефону.**
   `GET /api/client/appointments?phone=` — без пароля отдаёт всю историю записей (даты, услуги, цены, мастер). Можно перебирать номера телефонов.
   Файл: `src/app/api/client/appointments/route.ts`.

4. **`/api/book` — нет проверки антиспам-капчи (Turnstile) и лимита запросов.**
   Можно накидать ботом кучу фейковых записей/пользователей.
   Файл: `src/app/api/book/route.ts`.

## 🟠 Приоритет 2 — Перед реальным запуском/продажей (блокеры)

5. **Создание первого админа (SUPERADMIN) при установке.**
   Сейчас — вручную через `npx prisma studio`. В seed-скрипте вообще есть дефолтный логин/пароль (`admin@somique.com / password123`) — это дыра, если он попадёт в продакшн.
   → Нужен CLI-скрипт (`scripts/create-admin.ts`, по образцу `consent-cli.ts`) с флагами `--email --password --name`, который поднимает SUPERADMIN без ручного лазания в базу.

6. **Загрузка файлов (логотип, фон) пишется на диск сервера.**
   На Vercel/serverless это не работает — файлы пропадают при передеплое.
   Файл: `src/app/api/upload/route.ts`. Нужно object storage (Vercel Blob / S3 / R2).

7. **Мастера прибиты гвоздями в коде (`olga`, `yuliia`).**
   Новый салон не может завести своих мастеров без правки кода.
   Файлы: `src/config/masters.ts`, `src/config/masters.server.ts`.

8. **Google Calendar/Sheets ID — через переменные окружения на каждого мастера.**
   Не настраивается через UI, завязано на пункт 7.

9. **Пароли мастеров хранятся в открытом виде** (`plainPassword` в базе) — не только хэш, а ещё и читаемый пароль. Утечка базы = утечка паролей.

10. **Ключ шифрования (`AUTH_SECRET`) может тихо остаться пустым**, и тогда все секреты (OAuth, SMTP) шифруются публично известным значением, а при ошибке — вообще сохраняются в открытом виде без предупреждения.

11. **Нет упакованного способа развернуть приложение** — ни Docker, ни единой команды установки. Каждая продажа = ручная последовательность действий.
